# 1.1.0 — Unreleased

## Performance

| Tag | Change |
|---:|---|
| ![bugfix] | <details><summary>Stats console no longer crashes under a queued burst of messages (#ISS-005)</summary><br>**Root cause:** every message wrote straight into the widgets and rebuilt the per-row progress bars, re-applying their stylesheets. A queued burst of ~1000 messages delivered with the window shown terminated the process with a stack overflow.<br><br>**Fix:** a message now only updates the counters and raises a dirty flag; the widgets are written from a 100 ms timer, and each row's progress bar is created once and reused.<br><br>**Effect:** 535 → 2.2 microseconds per message.</details> |
| ![improvement] | <details><summary>Table, tree and combined consoles coalesce their message queues</summary><br>The queues are flushed at most once per 100 ms instead of once per event-loop turn — which, under a live producer, meant once per message.<br><br>**Effect:** table-view streaming 1111 → 12 microseconds per message.</details> |
| ![improvement] | <details><summary>`FilePlotter` keeps a single `QTextStream` open for the file's lifetime</summary><br>Previously a stream was constructed and the UTF-8 codec re-applied for every message. The stream is still flushed on every write, so durability is unchanged.<br><br>**Effect:** 36 → 15 microseconds per message.</details> |
| ![improvement] | `NativeConsoleView` caches logger info per `LoggerID` instead of doing a locked `LogManager` query and a full `LogObject::Info` copy per message |
| ![improvement] | <details><summary>Measured end-to-end effect across all receivers</summary><br>4000 queued plus 1000 streamed messages, Release / Qt 5:<ul><li>Burst drain 569 → 24 microseconds per message</li><li>Streaming 1244 → 30 microseconds per message</li></ul>Verified green on Qt 5 and Qt 6 — 16 checks pass, 0 fail.</details> |

## API

| Tag | Change |
|---:|---|
| ![feature] | New public methods `isStickToBottom()`, `hasActiveTextSelection()` and `clearTextSelection()` on both `QConsoleWidget` and `QContextLoggerTreeWidget` |
| ![feature] | <details><summary>Collapse the entire settings/filter column via `setSubWidgetCollapsed`/`isSubWidgetCollapsed` (`SubWidget::settingsFrame`) + `subWidgetCollapsedChanged` signal</summary><br>The left filter column collapses horizontally to a thin left strip with a single toggle so the console reclaims width. Starts expanded.</details> |
| ![feature] | <details><summary>New `Utilities/QtCompat.h` header exposing `Log::Utilities::connectCheckBoxStateChanged()`</summary><br>Qt 6.9 deprecated `QCheckBox::stateChanged(int)` in favour of `checkStateChanged(Qt::CheckState)`. The helper selects the correct signal at compile time, so the library's public `int`-taking slots keep their signatures — they are virtual and are overridden by downstream user subclasses.<br><br>Exported through the `Logger.h` umbrella header, so it is available to users of the library as well.</details> |
| ![feature] | <details><summary>New `MessageFilter::filterByLoggerID(LoggerID)` virtual hook for filtering by logger identity (#ISS-001)</summary><br>Default implementation accepts every logger, so existing message-only filters are unaffected. `LoggerIDFilter` now implements this hook and its `filter(Message)` delegates to it, so a single decision drives both message and logger-lifecycle filtering.</details> |
| ![bugfix] | <details><summary>Plot files are written as UTF-8 — non-ASCII characters are no longer destroyed on disk (#ISS-003)</summary><br>**Root cause:** `FilePlotter` wrote through `QTextStream` without setting a codec, so Qt fell back to the system locale codepage (CP1252 on a German Windows). Every character outside that codepage was irreversibly replaced before it reached the file.<br><br>**Fix:** both `QTextStream` sites now select UTF-8 through a local `setUtf8()` helper — `setCodec("UTF-8")` on Qt 5, `setEncoding(QStringConverter::Utf8)` on Qt 6.<br><br>Reported downstream by SwOptionEditor as ISSUE-064. Covered by the new `TST_filePlotterEncoding` test.</details> |
| ![feature] | <details><summary>`setRefreshInterval()` / `getRefreshInterval()` expose the UI coalescing interval</summary><br>Available on `QConsoleWidget`, `QConsoleView`, `QTreeConsoleView`, `QCombinedConsoleView` and `QStatsConsoleView`. Default 100 ms.</details> |
| ![bugfix] | <details><summary>Reparenting a logger into its own subtree is refused instead of closing a loop (#ISS-006)</summary><br>**Root cause:** `LogManager::onChangeParentInternal` accepted any parent, so a cycle could be created in the logger tree; `isChildOf` then walked the resulting unbounded chain.<br><br>**Fix:** a reparent that would close a loop is rejected and emits nothing, and `isChildOf` is bounded by the logger count. `QContextLoggerTreeWidget::TreeData::setParent` refuses to become a child of its own descendant as well, covering the file-load path that replays reparents straight into the views without passing through `LogManager`.</details> |

The identical latent bug in the tree console (`currentItemChanged`) is fixed the same way (`itemPressed`).</details> |
| ![feature] | Escape clears the in-cell text selection on both the table and tree consoles (handled in the view key handler and in the editor delegate's event filter), releasing the follow-pause so stick-to-bottom resumes |
| ![feature] | <details><summary>Tree console gained the same stick-to-bottom mechanic as the table</summary><br>On by default; unsticks on manual scroll-up; re-engages when scrolled back to the bottom; pauses while a text selection is active.<br><br><ul><li>Programmatic scrolls are guarded</li><li>`rangeChanged` re-clamps to the bottom while sticky</li><li>The update timer periodically reconciles the state</li></ul></details> |
| ![improvement] | Vertical timeline background (column tints, horizontal grid lines, column dividers, axis lines) is painted down to the full view height instead of stopping at the leading-edge margin; a tick label that would be clipped by the bottom edge is skipped |
| ![bugfix] | <details><summary>Logger contexts no longer appear twice in the context list</summary><br>**Root cause:** pre-existing loggers were replayed to `QAbstractLogWidget::onNewLogger` through two independent paths — the view-constructor replay (`postConstructorInit`) and the `SignalReceiver` replay — each adding a duplicate `QCheckBox` row and orphaning the first from `m_contextData`.<br><br>**Fix:** added an existence guard at the top of `onNewLogger` (early-return if the LoggerID is already tracked), mirroring the guard in `QContextLoggerTreeWidget::addContext`. Also fixes check-all/uncheck-all not toggling the duplicate row, since only tracked entries were iterated.</details> |
| ![feature] | <details><summary>Vertical timeline Present/Past modes</summary><br>Present follows wall-clock live; Past anchors the time axis to the loaded log file's timestamp range and never auto-advances, so loaded history stays visible. Auto-switches to Past on file load and back to Present on clear. The LogViewer example adds an "Ansicht" menu to toggle manually.</details> |
| ![improvement] | Vertical timeline maximum zoom raised from 20000 to 200000 px/s so bursts of simultaneous events spread far enough apart to read individually |
| ![improvement] | Filter panels sized to content: Loglevel / Date-Time / Edit panels fit exactly (no scrollbars); Context filter stretches to fill remaining vertical space |
| ![bugfix] | Loaded log-file data now populates the vertical-timeline and stats views (previously only the table and tree received it); a load flag prevents live data being double-counted |

| ![feature] | <details><summary>New automated regression example `Examples/StickyReproTest`</summary><br>Scripts the tab-switch/scroll/selection scenarios through the real Qt input pipeline (QTest) against `QCombinedConsoleView` and prints `[RESULT] PASS/FAIL`.<br><br>Phases: baseline follow, tab round-trip with timeline drag, unstick/re-engage, selection pause, Escape resume, and the full tree-view equivalents.</details> |
| ![feature] | Base widget adds virtual hooks `onMessagesLoadStarted()` / `onMessagesLoaded()` around the file-load path |
| ![improvement] | <details><summary>`QLogMessageItemProxyModel` filter invalidation routed through private `beginFilterUpdate()` / `endFilterUpdate()` wrappers</summary><br>The wrappers map to `beginFilterChange()` / `endFilterChange()` on Qt >= 6.10 and to `invalidateFilter()` below that.<br><br>All 6 filter setters (`setLevelVisibility`, `setContextVisibility`, `setTextFilter`, both `setDateTimeFilter` overloads and `clearDateTimeFilter`) now call `beginFilterUpdate()` as their first statement and `endFilterUpdate()` at the end, replacing the previous trailing `invalidateFilter()` calls. The reordering is required because `beginFilterChange()` must run *before* the filter state is mutated. `endFilterChange()` uses its default `Direction::Both`, exactly reproducing the old `invalidateFilter()` behaviour.</details> |
| ![improvement] | `QAbstractLogWidget` routes all 5 checkbox connections through the new `connectCheckBoxStateChanged()` helper |
| ![improvement] | <details><summary>High-DPI attributes guarded for Qt 6 in the 5 examples and the unit test</summary><br>`Qt::AA_EnableHighDpiScaling` and `Qt::AA_UseHighDpiPixmaps` are wrapped in `#if QT_VERSION < QT_VERSION_CHECK(6, 0, 0)` in the 5 example `main.cpp` files and in `unitTests/ExampleTest/main.cpp` — they are deprecated no-ops on Qt 6. `setHighDpiScaleFactorRoundingPolicy()` is deliberately left unguarded, as it is valid on both majors.</details> |
| ![bugfix] | <details><summary>Receiver filters now apply to logger lifecycle events, not just messages (#ISS-001)</summary><br>**Root cause:** `onNewLogger`, `onLoggerInfoChanged`, `onChangeParent` and the constructor snapshot bypassed the receiver's filters, so a receiver scoped to one run-root still saw the full logger tree — leaking cross-run context between receivers on a shared `LogManager`.<br><br>**Fix:** route those lifecycle paths through the receiver's filters via the new `filterByLoggerID` hook, so a scoped receiver captures only its own run-root and descendants regardless of subscribe order.</details> |
| ![bugfix] | <details><summary>`LoggerIDFilter` copy/assign no longer drops `m_includeChildren` (#ISS-002)</summary><br>The copy-constructor, `operator=` and `operator==` ignored `m_includeChildren`, so a copied filter silently reverted to the default and comparisons treated differing values as equal. All three now carry and compare the flag.</details> |
| ![feature] | New `TST_receiverFilter` unit test covering scoped receiver filtering across lifecycle events and the `LoggerIDFilter` copy/assign fix; wired into `ExampleTest` |
| ![feature] | New `TST_filePlotterEncoding` unit test — logs a string containing `ü`, reads the produced file as raw bytes and asserts the UTF-8 sequence `C3 BC` is present and the CP1252 byte `FC` is absent; wired into `ExampleTest` (#ISS-003) |
| ![improvement] | <details><summary>All four receiver slots are now profiled consistently across every receiver</summary><br>`LOGGER_RECEIVER_PROFILING_FUNCTION` was added everywhere it was still missing, so `onNewLogger`, `onLoggerInfoChanged`, `onLogMessage` and `onChangeParent` all show up in the profiler.<br><ul><li>The four `Internal::SignalReceiver` slots in `AbstractReceiver.cpp` — the signal entry point had no profiling at all before</li><li>The four `QAbstractLogWidget` base-class slots at `LOGGER_COLOR_STAGE_2`, which also covers `QStatsConsoleView` and `QVerticalTimelineView` for `onChangeParent` (they do not override it)</li><li>The four `FilePlotter` slots</li><li>The previously missing `onLoggerInfoChanged` in `QStatsConsoleView` and `QVerticalTimelineView`</li></ul></details> |
| ![feature] | <details><summary>New `TST_receiverLoadBenchmark` — a load benchmark for the receiver pipeline</summary><br>Two phases: messages queued with the Qt event loop never running and then drained in one go, and messages delivered one `processEvents()` at a time.<br><br>Runtime knobs `BENCH_BURST`, `BENCH_STREAM`, `BENCH_VIEWS` and `BENCH_SHOW`; writes `ReceiverLoadBenchmark.prof` in the profiling build.</details> |
| ![feature] | New `TST_receiverRegressions` unit test pinning both crashes — a shown-window queued burst through `QStatsConsoleView` (#ISS-005) and rejection of cyclic logger parents (#ISS-006) |
