# 1.1.0 — Unreleased

## API

| Tag | Change |
|---:|---|
| ![feature] | New public methods `isStickToBottom()`, `hasActiveTextSelection()` and `clearTextSelection()` on both `QConsoleWidget` and `QContextLoggerTreeWidget` |
| ![feature] | <details><summary>Collapse the entire settings/filter column via `setSubWidgetCollapsed`/`isSubWidgetCollapsed` (`SubWidget::settingsFrame`) + `subWidgetCollapsedChanged` signal</summary><br>The left filter column collapses horizontally to a thin left strip with a single toggle so the console reclaims width. Starts expanded.</details> |
| ![feature] | <details><summary>New `Utilities/QtCompat.h` header exposing `Log::Utilities::connectCheckBoxStateChanged()`</summary><br>Qt 6.9 deprecated `QCheckBox::stateChanged(int)` in favour of `checkStateChanged(Qt::CheckState)`. The helper selects the correct signal at compile time, so the library's public `int`-taking slots keep their signatures — they are virtual and are overridden by downstream user subclasses.<br><br>Exported through the `Logger.h` umbrella header, so it is available to users of the library as well.</details> |

## UI / UX

| Tag | Change |
|---:|---|
| ![feature] | Vertical timeline columns are ordered by context parent/child tree (DFS) instead of flat alphabetical |
| ![feature] | Stacked group-header rows above the per-context header, one per tree depth in use, drawing tinted ancestor-name bars spanning visible descendants with `[+]`/`[-]` toggles |
| ![feature] | <details><summary>Recursive collapse/expand per context in vertical timeline</summary><br>Clicking a group bar's glyph or a per-context header toggles that node's `collapsed` state. Descendants of any collapsed ancestor fold their dots/bubbles onto the ancestor's axis; source-context color is preserved on the dot ring and a small chevron marks descendant-origin dots. Ancestor-chain walk is cycle-guarded.</details> |
| ![improvement] | `Lane` gained `parentId` + `collapsed`; `topMargin()` grows with tree depth; `updateWidthHint()` skips lanes hidden by an ancestor collapse |
| ![bugfix] | Vertical timeline no longer snaps back to the newest time when a drag is released — live-follow re-engages only on right-click or when scrolling back to the leading edge (fixed leading-edge distance check in `maybeReenableFollowLive`) |
| ![bugfix] | <details><summary>Table console stick-to-bottom made robust</summary><br>The follow flag is driven only by genuine user scroll actions: `QAbstractSlider::actionTriggered` arms a one-shot marker and the synchronous `valueChanged` evaluates value and maximum together — so Qt-internal scrolls (tab-switch layout restore, geometry updates) can never flip it, and re-engaging at the bottom works under continuous message load.<br><br><ul><li>Programmatic scrolls are guarded</li><li>`QScrollBar::rangeChanged` re-clamps to the bottom while sticky (covers stale geometry after tab switches)</li><li>Samples while hidden are ignored</li></ul></details> |
| ![bugfix] | <details><summary>Table console stopped following after visiting another tab</summary><br>**Root cause:** the in-cell text-selection editor was opened from `currentChanged`, which also fires for focus-driven current-index changes on tab return — creating an invisible editor that silently paused auto-follow.<br><br>**Fix:** the editor now opens only on a genuine left-click (`pressed` signal). The identical latent bug in the tree console (`currentItemChanged`) is fixed the same way (`itemPressed`).</details> |
| ![feature] | Escape clears the in-cell text selection on both the table and tree consoles (handled in the view key handler and in the editor delegate's event filter), releasing the follow-pause so stick-to-bottom resumes |
| ![feature] | <details><summary>Tree console gained the same stick-to-bottom mechanic as the table</summary><br>On by default; unsticks on manual scroll-up; re-engages when scrolled back to the bottom; pauses while a text selection is active.<br><br><ul><li>Programmatic scrolls are guarded</li><li>`rangeChanged` re-clamps to the bottom while sticky</li><li>The update timer periodically reconciles the state</li></ul></details> |
| ![improvement] | Vertical timeline background (column tints, horizontal grid lines, column dividers, axis lines) is painted down to the full view height instead of stopping at the leading-edge margin; a tick label that would be clipped by the bottom edge is skipped |
| ![bugfix] | <details><summary>Logger contexts no longer appear twice in the context list</summary><br>**Root cause:** pre-existing loggers were replayed to `QAbstractLogWidget::onNewLogger` through two independent paths — the view-constructor replay (`postConstructorInit`) and the `SignalReceiver` replay — each adding a duplicate `QCheckBox` row and orphaning the first from `m_contextData`.<br><br>**Fix:** added an existence guard at the top of `onNewLogger` (early-return if the LoggerID is already tracked), mirroring the guard in `QContextLoggerTreeWidget::addContext`. Also fixes check-all/uncheck-all not toggling the duplicate row, since only tracked entries were iterated.</details> |
| ![feature] | <details><summary>Vertical timeline Present/Past modes</summary><br>Present follows wall-clock live; Past anchors the time axis to the loaded log file's timestamp range and never auto-advances, so loaded history stays visible. Auto-switches to Past on file load and back to Present on clear. The LogViewer example adds an "Ansicht" menu to toggle manually.</details> |
| ![improvement] | Vertical timeline maximum zoom raised from 20000 to 200000 px/s so bursts of simultaneous events spread far enough apart to read individually |
| ![improvement] | Filter panels sized to content: Loglevel / Date-Time / Edit panels fit exactly (no scrollbars); Context filter stretches to fill remaining vertical space |
| ![bugfix] | Loaded log-file data now populates the vertical-timeline and stats views (previously only the table and tree received it); a load flag prevents live data being double-counted |
| ![bugfix] | Fixed mojibake in the LogViewer "Datei" menu German umlaut (now uses an `Ö` escape) |

## Build & Dependencies

| Tag | Change |
|---:|---|
| ![feature] | LogViewer builds as a Windows GUI-subsystem app (no native console window) via an opt-in `EXAMPLE_WIN32_GUI` flag in `ExampleMaster.cmake` |
| ![removal] | Removed the trailing `getchar()` and unused `<iostream>` from the LogViewer example |
| ![feature] | <details><summary>The library now builds against both Qt 5 and Qt 6</summary><br>The Qt major version is picked with `set_if_not_defined(QT_MAJOR_VERSION ...)` in `CMakeLists.txt`; the default stays **5**, so existing setups are unaffected.<br><br>No CMake changes were needed — `QT_PACKAGE_NAME`, the `qt_wrap_internal_*` helpers and the `EntryPoint` (Qt 6) / `WinMain` (Qt 5) branch in `ExampleMaster.cmake` already handled both majors. The work was entirely in the sources: MSVC compiles Qt's `[[deprecated]]` markers as hard `error C4996`, so every Qt 6 deprecation was a build breaker.<br><br>**Verified:** full configure + build of core (all 3 profiles), all 7 examples and the unit tests under Qt 5.15.2 (msvc2019_64) and Qt 6.11.1 (msvc2022_64) — 0 errors, 0 warnings on both; `ExampleTest.exe` reports `All Tests: PASS` on the Qt 6 build.</details> |
| ![improvement] | Version guards are pinned to the Qt version in which each *replacement* API appeared (`checkStateChanged` 6.9, `endFilterChange` 6.10) rather than the version that deprecated the old API, so intermediate Qt 6.x releases keep using the then-current API |

## Internal

| Tag | Change |
|---:|---|
| ![feature] | <details><summary>New automated regression example `Examples/StickyReproTest`</summary><br>Scripts the tab-switch/scroll/selection scenarios through the real Qt input pipeline (QTest) against `QCombinedConsoleView` and prints `[RESULT] PASS/FAIL`.<br><br>Phases: baseline follow, tab round-trip with timeline drag, unstick/re-engage, selection pause, Escape resume, and the full tree-view equivalents.</details> |
| ![feature] | Base widget adds virtual hooks `onMessagesLoadStarted()` / `onMessagesLoaded()` around the file-load path |
| ![improvement] | <details><summary>`QLogMessageItemProxyModel` filter invalidation routed through private `beginFilterUpdate()` / `endFilterUpdate()` wrappers</summary><br>The wrappers map to `beginFilterChange()` / `endFilterChange()` on Qt >= 6.10 and to `invalidateFilter()` below that.<br><br>All 6 filter setters (`setLevelVisibility`, `setContextVisibility`, `setTextFilter`, both `setDateTimeFilter` overloads and `clearDateTimeFilter`) now call `beginFilterUpdate()` as their first statement and `endFilterUpdate()` at the end, replacing the previous trailing `invalidateFilter()` calls. The reordering is required because `beginFilterChange()` must run *before* the filter state is mutated. `endFilterChange()` uses its default `Direction::Both`, exactly reproducing the old `invalidateFilter()` behaviour.</details> |
| ![improvement] | `QAbstractLogWidget` routes all 5 checkbox connections through the new `connectCheckBoxStateChanged()` helper |
| ![improvement] | <details><summary>High-DPI attributes guarded for Qt 6 in the 5 examples and the unit test</summary><br>`Qt::AA_EnableHighDpiScaling` and `Qt::AA_UseHighDpiPixmaps` are wrapped in `#if QT_VERSION < QT_VERSION_CHECK(6, 0, 0)` in the 5 example `main.cpp` files and in `unitTests/ExampleTest/main.cpp` — they are deprecated no-ops on Qt 6. `setHighDpiScaleFactorRoundingPolicy()` is deliberately left unguarded, as it is valid on both majors.</details> |
